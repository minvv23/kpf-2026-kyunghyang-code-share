# 처리 흐름

```
기사 메타데이터 (CMS 내보내기 등)          성과 지표 (자사 통계, 포털 통계)
            │                                        │
            └──────────── build_dataset ─────────────┘
                              │  기사 ID 기준 병합, 집계 기간 합산
                              ▼
                     dataset/YYYYMMDD.json
                              │
                     extract_attributes (LLM)
                              │  주제, 논조, 자극성, 읽기 쉬움, 객관성, 수치 포함
                              ▼
                     text_features (기본 변수)
                              │
              ┌───────────────┴───────────────┐
              ▼                               ▼
        train_model                       interpret
   (LightGBM, MAE·RMSE·R²)          (표준화 선형회귀 계수)
              └───────────────┬───────────────┘
                              ▼
                      model/YYYYMMDD.json
                              │
                       monthly_report
                              ▼
                  report/month_YYYYMM.json  →  web/index.html
```

## 단계별 설명

1. **수집 (`collect_metrics`)**: 통계 시스템에서 기사별 조회수, 체류시간, 포털 유입을 받는다.
   연동 방식은 언론사마다 다르므로 `MetricsSource`를 구현한다. 예시로 CSV 구현을 넣었다.
2. **병합 (`build_dataset`)**: 기사 ID를 정규화하고, 발행일부터 `LABEL_DAYS` 동안의 지표를 합산해 붙인다.
3. **속성 추출 (`extract_attributes`)**: 제목과 본문을 LLM에 넣어 정해진 스키마로 점수를 받는다.
   스키마를 벗어난 응답은 검증 단계에서 걸러지고 재시도한다.
4. **기본 변수 (`text_features`)**: 제목 길이, 본문 길이, 문장·문단 수, 말머리 여부, 발행 시각·요일.
5. **예측 모델 (`train_model`)**: 로그 변환한 성과를 LightGBM 회귀로 학습하고, 최근 구간으로 평가한다.
6. **해석 (`interpret`)**: 변수를 표준화해 선형회귀하고 계수와 유의수준을 정리한다.
7. **월간 리포트 (`monthly_report`)**: 달력 월 단위로 KPI, 분야별 요약, 인기 기사, 요인 표를 묶는다.

## 운영 시 고려사항

- 속성 추출 모델을 바꾸면 과거 기사 속성도 같은 모델로 다시 추출해야 학습과 예측의 기준이 맞는다.
- 통계 시스템 계정·주소 같은 비밀 값은 환경변수나 비밀 관리 도구로 주입하고 저장소에 올리지 않는다.
- 하이퍼파라미터와 학습 기간은 각사 데이터 규모에 맞춰 정한다.
